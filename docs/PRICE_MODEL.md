# Collex Price Intelligence

**Model Version**: 1.0  
**Service**: `ml-service/` (Python 3.14 / FastAPI)  
**Endpoint**: `POST /api/v1/ml/price/predict` (via Node.js proxy)

---

## Overview

Collex Price Intelligence estimates a fair second-hand selling price range for campus goods. It helps sellers avoid underpricing (losing value) or overpricing (no buyer interest), and helps buyers understand if a listed price is reasonable.

The model is **deliberately honest about uncertainty**. If training data coverage for a specific input is low, it returns `confidence: "LOW"` and explains this in the UI. No false confidence is shown to users.

---

## Training Data

### Format

A CSV with one row per estimated campus transaction:

| Column | Type | Description |
|--------|------|-------------|
| `category` | enum | Item category (TEXTBOOKS, ELECTRONICS, etc.) |
| `brand` | string | Brand name, empty string if unknown |
| `original_price` | int (INR) | Original purchase price |
| `age_months` | int | Months since purchase |
| `condition` | enum | BRAND_NEW, LIKE_NEW, GOOD, FAIR |
| `listing_type` | enum | SELL, RENT, EXCHANGE |
| `campus` | string | College name |
| `sale_price` | int (INR) | **Target**: estimated fair resale price |

### Current data source

**Synthetic** - generated by `ml-service/data/generate_dataset.py` using empirically grounded domain knowledge:
- Condition depreciation bands (e.g., GOOD condition retains 35-55% of original value)
- Age depreciation factors (e.g., items >4 years old retain ~35%)
- Category-specific price ranges sourced from typical Indian campus goods
- 3,000 rows generated with `random.seed(42)` for reproducibility

### Why synthetic data is used right now

No real historical sale data exists yet (Collex is in early development). The synthetic data encodes real-world depreciation intuition from:
- Indian e-commerce return policies
- Typical campus secondhand market behavior
- OLX/Quikr category price patterns for students

**In production**, this dataset will be replaced/augmented with actual completed transaction prices from MongoDB.

## Features

| Feature | Type | Preprocessing | Why? |
|---------|------|---------------|------|
| `category` | categorical | One-hot encode | Price ranges differ wildly by category |
| `condition` | categorical | One-hot encode | Most significant single depreciation factor |
| `listing_type` | categorical | One-hot encode | Rent prices are a fraction of sell prices |
| `original_price` | numeric | passthrough | Direct price anchor |
| `age_months` | numeric | passthrough | Non-linear depreciation with age |
| `price_to_age_ratio` | numeric (engineered) | passthrough | Captures value-density of newer items |
| `brand_present` | binary (0/1) | passthrough | Branded items command a small premium |

**Not used**: campus (insufficient variance in synthetic data; will help in production), description text (future NLP feature).

## Algorithm

**RandomForestRegressor** (scikit-learn)

```python
RandomForestRegressor(
    n_estimators=200,
    max_depth=12,
    min_samples_leaf=4,
    random_state=42,
    n_jobs=-1,
)
```

**Why RandomForest over Linear Regression?**

| Concern | Linear Regression | RandomForest |
|---------|-------------------|--------------|
| Price range spans Rs10-Rs80,000 | Outliers distort | Robust |
| Non-linear depreciation | Poor fit | Handles naturally |
| Mixed feature types | Requires scaling | None needed |
| Interpretability | Formula visible | Feature importance available |
| Overfitting on small dataset | Low risk | Moderate risk (mitigated by `min_samples_leaf=4`) |

**Preprocessing pipeline** (`sklearn.pipeline.Pipeline`):
```
ColumnTransformer:
  -> OneHotEncoder (handle_unknown="ignore")  for categorical features
  -> passthrough                               for numeric features
-> RandomForestRegressor
```

## Evaluation Metrics

Evaluated on a held-out 20% test split (600 rows) from the synthetic dataset:

| Metric | Value | Meaning |
|--------|-------|---------|
| **MAE** | Rs231.88 | On average, predictions are off by Rs232 |
| **RMSE** | Rs638.32 | Reflects wide price range (Rs10-Rs57,810) |
| **R2** | 0.973 | Model explains 97.3% of price variance |
| **MAPE** | 20.43% | Average percentage error is ~20% |

> **Important**: These metrics are from the *synthetic* dataset and reflect how well the model learned the rules it was trained on. Real-world accuracy on actual campus transactions will differ. Do not show these exact metrics to end users.

## Confidence Levels

The API returns `confidence: "HIGH" | "MEDIUM" | "LOW"` based on:

1. **Coefficient of variation** (CV = std of individual tree predictions / mean): how much the 200 trees agree
2. **Model's test MAPE**: a baseline uncertainty estimate

| Confidence | Condition |
|-----------|-----------|
| HIGH | CV < 20% AND MAPE < 20% |
| MEDIUM | CV < 40% AND MAPE < 35% |
| LOW | Otherwise |

The confidence note in the UI is always honest. LOW confidence explicitly tells the user to verify manually.

**Request** (`POST /api/v1/ml/price/predict`):
```json
{
  "category": "ELECTRONICS",
  "condition": "GOOD",
  "listing_type": "SELL",
```

```json

  "recommended_price": 2230,

  "upper_bound": 2690,

    "brand_factor": "Brand 'Samsung' may command a small premium...",
    "model_algorithm": "RandomForestRegressor (n_estimators=200, max_depth=12)"
  }
}
```

## Limitations

1. **Synthetic training data**: The model has not seen real campus sale prices. Until real transactions accumulate, all estimates are based on domain heuristics, not empirical data.

2. **MAPE of ~20%**: On a Rs5,000 item, the estimate may be off by Rs1,000. Acceptable as a starting point but not as a definitive price.

3. **No text features**: The item title and description are not used. A "Casio fx-991EX" and a "Scientific Calculator (unknown brand)" would get the same estimate even though they may trade very differently.

4. **Age input is coarse**: The SellItemPage currently defaults `age_months=12`. A future explicit age field would improve accuracy significantly.

5. **No campus-specific pricing**: The model cannot learn demand differences between campuses without real transaction data.

6. **No seasonal effects**: Semester end (mass selling) and semester start (mass buying) affect campus prices. No time-of-year feature exists yet.

## Interview Defense

**"Why RandomForest instead of a neural network?"**

For 3,000 rows, a neural network would almost certainly overfit. RandomForest is the right tool at this scale: interpretable via feature importances, no feature scaling needed, and gives calibrated uncertainty via individual tree variance.

**"Your MAPE is 20% - is that acceptable?"**

It is honest. For a price suggestion used as a guide (not a binding contract), +/-20% is meaningful guidance. We explicitly tell users the confidence level. If this were a financial product, we would need better. For campus price discovery, it is a useful signal.

**"How would you improve this?"**

The biggest lever is real data. One semester of actual Collex transactions would outperform any algorithmic improvement to the model. After that: add item age as an explicit input, and build separate models per broad category (Electronics vs Textbooks behave very differently).
